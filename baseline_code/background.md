# BDC 2026 C 赛题背景与参赛要点

整理时间：2026-05-31  
主要来源：清华大学大数据挑战赛官网及其下载文件；另结合当前 baseline 中的数据说明和评分脚本核对数据/评分细节。

## 1. 赛题背景

本赛题为 **C. 量化投资中的机器学习**，目标是在沪深 300 成分股范围内，利用机器学习预测未来一周收益率最高的股票组合。

核心任务：

- 从沪深 300 成分股中选择 **不超过 5 只股票**。
- 为每只股票分配权重，组合权重总和要求 **0 到 1 之间**。
- 预测窗口为“未来一周”，官网评价口径落到 **未来 5 个交易日开盘价收益**。
- 排名依据为预测组合相对真实行情计算得到的加权收益率。

建模启发：

- 这是排序/组合选择问题，不只是单股涨跌二分类。
- 目标应更贴近“未来 5 个交易日 open-to-open 收益率”。
- 选股和配权都影响得分；baseline 默认 Top5 等权重 0.2，但规则允许改权重，也允许不满仓。
- 必须严格避免使用预测日之后的信息，尤其是未来开盘价、收盘价和未来成分股变化等潜在泄漏。

## 2. 数据与格式

官网说明数据格式、范围、来源均不作限制，参赛者可以使用其他能够免费公开下载的数据，但需要标明数据来源，并遵守参赛须知中关于外部数据/开源模型报备和许可的要求。

官方 baseline 使用的数据要点：

- 股票范围：沪深 300 指数成分股，约 300 只；baseline 数据工具以 2026-02-20 的成分股列表为基准。
- 默认历史范围：2015-01-01 至 2026-02-28，可在 `get_stock_data.py` 中修改起止日期。
- 数据来源：baseline 数据抓取工具使用 Baostock。
- 复权方式：后复权数据，已处理分红、配股、拆股等除权除息事项。
- 本地主要数据文件：`data/stock_data.csv`、`data/train.csv`、`data/test.csv`。

baseline CSV 字段：

| 字段 | 含义 |
| --- | --- |
| `股票代码` | 股票代码。baseline 本地训练数据里可能是映射后的数字 ID，最终提交需用真实 6 位股票代码。 |
| `日期` | 交易日日期。 |
| `开盘` | 开盘价。 |
| `收盘` | 收盘价。 |
| `最高` | 最高价。 |
| `最低` | 最低价。 |
| `成交量` | 成交股数。 |
| `成交额` | 成交金额。 |
| `振幅` | 当日振幅百分比。 |
| `涨跌额` | 涨跌金额。 |
| `换手率` | 换手率百分比。 |
| `涨跌幅` | 涨跌幅百分比。 |

baseline 训练逻辑补充：

- 默认序列长度为 60 个交易日。
- 特征工程包含基础量价字段、39 个技术指标，以及可选的 `158+39` 特征组合。
- 训练标签在代码中用 `open_t1` 到 `open_t5` 的相对收益构造：
  `label = (open_t5 - open_t1) / open_t1`。
- 按“日期”组织训练样本，同一天内多只股票一起排序。

## 3. 提交文件与输出格式

在线阶段提交 `result.csv`，格式如下：

```csv
stock_id,weight
600000,0.2
000001,0.2
```

硬性要求：

- 第一列为 `stock_id`，第二列为 `weight`。
- 最多提交 5 只股票。
- 股票代码不能重复。
- 权重总和必须大于等于 0 且小于等于 1；未使用权重相当于持有现金，现金收益为 0。
- `result.csv` 需使用 UTF-8 编码。

本地 baseline 评分脚本也兼容中文列名 `股票代码` / `权重`，但正式提交建议严格使用官网要求的 `stock_id,weight`。

## 4. 评价指标

官网指标是组合的 5 日加权收益率。对每只入选股票：

```text
单股收益率 = (第 5 个交易日开盘价 - 第 1 个交易日开盘价) / 第 1 个交易日开盘价
组合得分 = sum(单股收益率_i * 权重_i)
```

本地 `test/score_self.py` 的实现与该口径一致：

- 读取 `output/result.csv`。
- 在 `data/test.csv` 中筛选预测股票。
- 每只股票取测试集最后 5 条记录。
- 用第一条记录的 `开盘` 和最后一条记录的 `开盘` 计算收益率。
- 按提交权重加权求和，得到 `Final Score`。

注意事项：

- 指标方向红线：正式 `Final Score` / 组合得分 **越高越好**；训练过程中的 `Loss` 仅为内部优化损失，通常越低越好，但不能替代最终排序指标。
- 正式排名按所有队伍提交结果的加权收益率排序，收益率越高排名越靠前。
- 最终成绩需要超过赛事方基准模型才进入奖励候选；低于基准模型不计入奖励。
- baseline 训练时日志中的归一化 `final_score` 只是内部验证指标，不等同于官网最终 `Final Score`。

## 6. Docker、复现与代码要求

复现要求：

- 代码需要固定随机种子，训练结果应能精确复现。
- 训练运行时间上限：8 小时。
- 推理运行时间上限：5 分钟。
- 官方复现机器配置参考：Intel i7-13650H、16GB 内存、RTX 4060 8GB、50GB 存储。
- Docker 镜像、模型、数据合计不超过 10GB，解压后不超过 10GB。
- 测试环境不提供网络，所有依赖、数据、模型权重必须打包在 Docker 中。

推荐工程要求：

- 根目录保留 `train.sh` 和 `test.sh`。
- `train.sh` 用于训练并保存模型。
- `test.sh` 用于加载模型并生成 `output/result.csv`。
- `README.md` 应写清楚环境配置、数据来源、预训练/外部模型使用、算法思路、训练流程和推理流程。
- 如使用公开数据或公开预训练模型，需要在规定时间前向组委会报备来源、获取方式和用途。

baseline 打包流程：

- 本地运行 `sh train.sh` 或 Windows 下运行 `python code/src/train.py`。
- 本地运行 `sh test.sh` 或 Windows 下运行 `python code/src/predict.py`。
- 确认 `output/result.csv` 生成。
- 使用 Docker 构建镜像并导出 `.tar` 文件，供进入复现名单后提交。

## 7. 参赛规则与风险点

重要规则：

- 每队 1 到 3 名学生，可设置 1 名指导教师；每位选手只能参加一支队伍。
- 参赛作品必须是团队原创，不能复制他人方案。
- 比赛期间不得公开、泄露、交换比赛数据、代码、模型或结果。
- 不得攻击或利用平台漏洞；发现漏洞应及时报告组委会。
- 赛事数据只能用于本次比赛，赛后需删除或销毁。
- 不允许使用自动化脚本频繁提交、恶意占用平台资源。

容易踩坑的点：

- `stock_id` 必须是提交口径下的股票代码，不要误提交训练内部映射 ID。
- 权重总和可以小于 1，但不能超过 1。
- 评价用开盘价，不是收盘价。
- 本地切分测试集时应保证最后 5 个交易日作为 test，才与评分脚本口径一致。
- 如果扩展数据源，需要提前保存下载脚本、原始数据说明和来源链接，方便复现和报备。

## 8. 对建模的直接建议

- 以 5 日 open-to-open 收益为主目标，验证集也按相同口径回测。
- 优先优化 Top5 排序质量，而不是全体股票的平均误差。
- 输出层不必只等权：可以根据预测收益、风险、置信度或组合约束调整权重。
- 每个提交窗口对应一个具体预测日期，要确保训练数据只覆盖当时可获得的信息。
- 做本地回测时，用滚动时间切分，避免随机切分造成未来信息泄漏。
- 保留一份可复现实验记录：数据版本、特征版本、模型参数、随机种子、提交文件和分数。
