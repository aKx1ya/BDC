## Step 1：数据获取 Data Layer

### 一句话概括

**买菜 + 验菜 — 把比赛允许的、预测时真实可得的所有原始数据下载、整理、存好。不做任何加工。**

## Step 2：特征工程 Feature Layer

### 一句话概括

**备菜 — 把 Step 1 的原始 OHLCV 数据（买回来的菜），通过数学变换加工成有交易含义的衍生指标（切好、腌好、调好味的半成品）。不做预测，不做模型，纯粹是"把原始数字变成信号"。**

### 比喻

```
Step 1：买菜                              Step 2：备菜
───────────────                         ───────────────
┌─────────────────────┐                ┌──────────────────────┐
│ open    = 五花肉     │                │ ret_5   = 切成肉片    │
│ close   = 排骨       │                │ ma_20   = 腌制排骨    │
│ high    = 青菜       │    ──→        │ clv     = 青菜切段    │
│ low     = 葱姜蒜     │                │ MACD    = 调好的酱汁  │
│ volume  = 鸡蛋       │                │ vol_20  = 打好的蛋液  │
│ amount  = 面粉       │                │ rank    = 分盘装好    │
└─────────────────────┘                └──────────────────────┘

  从市场买回来的原始形态                 加工成随时可以下锅的状态
  不能直接下锅                         同一个原料不同做法：
                                         close → ret_5（切片）
                                               → ma_20（慢炖）
                                               → volatility_20（磨粉）
```

### 8 道加工工序

#### 第 1 道：基础清洗（策略 2.3）

```
做什么：去重、排序、缺失值填 0、无穷大处理
相当于：把菜洗干净，去掉烂叶子
```

#### 第 2 道：收益率特征（策略 2.4）

```
ret_1  = 今天收盘 / 昨天收盘 - 1        → 今天涨了多少
ret_5  = 今天收盘 / 5 天前收盘 - 1      → 这周涨了多少
ret_10 = 今天收盘 / 10 天前收盘 - 1     → 这两周涨了多少
ret_20 = 今天收盘 / 20 天前收盘 - 1     → 这个月涨了多少
ret_40 = 今天收盘 / 40 天前收盘 - 1     → 这两个月涨了多少

直觉：一只股票 ret_5=+8%, ret_20=-5%
     → 最近一周猛涨，但一个月维度还在跌
     → 可能是超跌反弹，或者趋势反转

✅ 已实现：ret_1, ret_3, ret_5, ret_10, ret_20, ret_40
```

#### 第 3 道：均线特征（策略 2.4）

```
ma_3  = 过去 3 天收盘价平均         → "极短期重心"
ma_5  = 过去 5 天收盘价平均         → "短期重心"
ma_10 = 过去 10 天收盘价平均        → "中期重心"
ma_20 = 过去 20 天收盘价平均        → "趋势重心"
ma_40 = 过去 40 天收盘价平均        → "长期重心"

close_to_ma_20 = 今天收盘 / ma_20 - 1  → 股价在均线上方(正)还是下方(负)？

直觉：股价在 ma_20 上方 → "站在均线上"，多头排列
     股价在 ma_20 下方 → "被均线压制"，空头排列

✅ 已实现：ma_3, ma_5, ma_10, ma_20, ma_40 + 各自的 close_to_ma
```

#### 第 4 道：波动率特征（策略 2.4）

```
volatility_5  = 过去 5 天日收益的标准差   → "这周有多闹腾"
volatility_10 = 过去 10 天               → "这两周"
volatility_20 = 过去 20 天               → "这个月"

直觉：volatility 高的股票 → 涨跌猛，机会大但风险也大
     volatility 低的股票 → 不温不火，稳但可能没惊喜

✅ 已实现：volatility_5, volatility_10, volatility_20
```

#### 第 5 道：成交量/成交额特征（策略 2.4）

```
amount_ma_3  = 过去 3 天成交额平均        → "最近流动性怎么样"
amount_ratio_3 = 今天成交额 / amount_ma_3 → 今天放量了吗？

直觉：amount_ratio_3 = 2.5 → 今天成交额是平时的 2.5 倍 → 放量，有资金关注
     amount_ratio_3 = 0.5 → 今天只有平时一半 → 缩量，没人玩

✅ 已实现：amount_ma_3/5/20, volume_ma_3/5/20, amount_ratio_3, volume_ratio_5
```

#### 第 6 道：K 线形态特征（策略 2.4）

```
一根日 K 线包含 4 个价格：

                    ← 最高 high
       ┌──────┐
       │ 实体  │    ← 开盘和收盘之间的"打架结果"
       │      │       收盘 > 开盘 = 阳线（买方赢了）
       └──────┘       收盘 < 开盘 = 阴线（卖方赢了）
       │      │
       │ 下影线│    ← 最低点
       └──────┘
                    ← 最低 low

从中提取的信号：

  clv（收盘位置）= ((close-low) - (high-close)) / (high-low)
    +1 = 收在最高，-1 = 收在最低，0 = 收在正中间

  lower_shadow_ratio（下影线占比）
    下影线很长 → 盘中跌下去但被拉回来了 → 下方有承接

  upper_shadow_ratio（上影线占比）
    上影线很长 → 冲高回落 → 上方有抛压

  body_ratio（实体大小）
    实体大 → 多空一方明显占优
    十字星 → 实体极小 → 多空胶着

  volume_close_strength（量价配合）
    = amount_ratio_3 × clv
    高 = 放量 + 收在高位 → 资金主动买入的迹象

✅ 已实现：clv, lower_shadow_ratio, upper_shadow_ratio, body_ratio, range_ratio, volume_close_strength
```

#### 第 7 道：横截面排名特征（策略 2.5）

```
和个股价量特征的区别：
  个股价量 = 只看自己（纵向，时间维度）
  横截面   = 和 300 只股票比（横向，同一天维度）

  ret_5_rank_pct = 今天这 300 只里，5 日涨幅排第几（0~1 之间）
    0.95 → 涨幅超过 95% 的股票 → 今天表现非常强
    0.05 → 涨幅只超过 5% 的股票 → 今天表现非常弱

直觉：一只股票涨了 2%，全市场都涨了 3% → 它其实算弱的
     一只股票涨了 2%，全市场跌了 1% → 它其实很强
     → 横截面排名消除了"水涨船高"的假象

✅ 已实现：ret_1/3/5/10/20/40、amount、volatility_20 的 rank_pct
```

#### 第 8 道：风险 + 行业 + 标签

```
风险特征（策略 2.10）：
  drawdown_20 = 当前价比 20 日最高点跌了多少
    例：-0.15 → 从 20 日高点跌了 15%
  max_drop_20 = 过去 20 天单日最大跌幅
    例：-0.08 → 过去 20 天最惨的一天跌了 8%

  → 第 6 步用来踢掉回撤太深、跌太猛的股票
  ✅ 已实现

行业动量特征（策略 2.7）：
  sector_momentum_3 = 行业近 3 日累计涨幅
  sector_momentum_rank_pct = 行业在 31 个行业中的排名

  ⚠️ 有代码但数据缺！因为 Step 1 没有行业分类数据
    所有 300 只股票归入 UNKNOWN → 行业动量 = 全市场均值 → 失效

标签（策略第 3 步，但在 Step 2 里提前构造）：
  label = (open_t5 - open_t1) / open_t1
  = 如果 T 日收盘后预测，T+1 开盘买入，T+5 开盘卖出，收益率是多少

  这是"答案"——只能作为模型学习的目标，绝对不能作为输入特征！
  如果模型训练时看到了 label → 作弊（未来信息泄漏）
  如果模型输入包含了 label → 回测分数虚高，正式评测崩溃
```

## Step 3：标签与样本 Sample Layer

### 一句话概括

**配菜出题 — 把 Step 2 的特征表，按「每天一道排序题」的方式打包：每天 300 只股票，每只看过去 60 天特征，目标是把未来涨最多的排到最前面。**

### 比喻

```
Step 1：买菜                    Step 2：备菜                    Step 3：配菜出题
───────────────               ───────────────                ─────────────────────
┌──────────────┐              ┌──────────────┐               ┌─────────────────────┐
│ 原始 OHLCV   │              │ 57 个特征     │               │ 每天一份"试卷"       │
│ 12 列原始数据 │   ──→       │ 8 道工序加工   │    ──→       │                     │
│              │              │ 切/腌/磨/调    │               │ 题目：300 只股票     │
│ 面粉/鸡蛋/糖 │              │              │               │ 线索：过去 60 天特征  │
└──────────────┘              └──────────────┘               │ 答案：未来 5 天涨跌幅  │
                                                             │ 目标：选出涨最多的 5 只 │
                                                             └─────────────────────┘

  从市场买回来的原料             加工成半成品                    出成一道道"排序题"
                                                            每天一题，共 460 题
```

### 核心概念：一个样本 ≠ 一只股票

```
传统 ML 思维（错误）：                      比赛需要的思维（正确）：
────────────────────────                  ─────────────────────────
一个样本 = 一只股票的一天                    一个样本 = 一个交易日
X = [ret_5, ma_20, clv, ...]             X = 300 只股票 × 60 天 × 34 特征
y = 涨还是跌                               y = 300 个 label（每只股票的未来收益）
                                         任务 = 把 300 只股票按收益从高到低排序
这是分类/回归问题                           这是排序问题（Learning to Rank）
```

**关键洞见**：模型不需要精确预测「这只股票涨 3.2%」，只需要知道「A 比 B 涨得多」。排序只需要相对顺序正确，不需要绝对值准确。

### 实际运行过程（逐行解读）

#### 第一步：加载 + 快速特征工程

```
📂 读取 data/train.csv（软链接 → Baseline /app/data/train.csv）
   156,590 行 × 12 列

列名标准化：股票代码→stock_id, 开盘→open, 收盘→close...
类型转换：数字列转 float，日期列转 datetime
去重排序：按 (stock_id, date) 去重，确保每只股票每天只有一行

然后跑精简版特征工程（与 Step 2 逻辑完全一致，但合并到一个脚本里）：
  - 收益率 ret_1/3/5/10/20
  - 均线 ma_3/5/10/20 + close_to_ma
  - 波动率 volatility_5/10/20
  - 量比 amount_ratio_3, avg_amount_3
  - K线形态 clv, volume_close_strength
  - 风险 drawdown_20, max_drop_20
  - 横截面排名 ret_X_rank_pct, amount_rank_pct, volatility_20_rank_pct
```

#### 第二步：构造标签

```
标签公式（比赛口径）：
  label = (open_T+5 - open_T+1) / open_T+1

  例：T 日收盘后做预测 → T+1 开盘价买入 → T+5 开盘价卖出
      T+1 开盘 = 10.00, T+5 开盘 = 10.50
      → label = +0.05 = +5%

为什么用开盘价而不是收盘价？
  → 策略文档设计：T日收盘后预测 → T+1开盘买入（可执行）→ T+5开盘卖出（可执行）
  → 如果用收盘价，T+1 开盘买入但用 T+1 收盘算收益 = 包含了当日日内涨跌 = 不真实

关键防泄漏检查：
  future_open_t1 和 future_open_t5 使用 shift(-1) / shift(-5)
  → 用到了"未来"数据，绝对不能作为特征输入模型
  → 这 2 列 + label 被标记为 LEAKAGE_COLS，后续步骤会从特征集中剔除
```

#### 第三步：过滤不合格样本

```
过滤规则 1 — 历史不足 60 天：
  每只股票前面 60 天没有足够的历史数据来算特征
  → 过滤条件：history_count ≥ 60
  → 运行结果：156,590 → 138,890（过滤 17,700 行，全是每只股票的前 59 天）

过滤规则 2 — 标签不完整：
  每只股票最后 5 天没有 T+5 数据（因为"未来"还没发生）
  → 过滤条件：label 不为 NaN
  → 运行结果：138,890 → 138,890（过滤 0 行，因为 shift 操作后末尾的 NaN 已被 fillna(0) 覆盖）

⚠️ 实际运行中发现 label 过滤为 0 行 —— 因为前面 fillna(0.0) 把所有 NaN 填成了 0。
   这意味着最后几天的 label = 0.0，虽然它们应该是 NaN（没有真实的 T+5 数据）。
   这是一个需要修复的问题 —— 应该在 fillna 之前先做 label 过滤。
```

#### 第四步：按日期打包成排序样本

```
460 个有效交易日 → 460 道"排序题"（修复后，过滤了 1,500 行无真实 label 的假样本）

每个交易日：

  - 每只股票：过去 60 天 × 34 个特征的序列

```

### 一个思维转折：从"预测涨跌"到"排序选股"

```
传统分类思路（很多新手会掉进去的坑）：
  "训练一个模型预测每只股票未来 5 天涨还是跌"
  → 问题：每天 300 只股票，可能 150 只涨 + 150 只跌
  → 模型输出 150 只"会涨"的股票 → 然后呢？选哪 5 只？

排序思路（本题正确做法）：
  "训练一个模型给 300 只股票打分，分数高的排在前面"
  → 不需要知道精确涨多少，只需要知道 A > B > C
  → 直接取 Top5，干净利落

为什么排序比分类更适合？
  1. 分类需要阈值（涨 > 0% 算正样本？涨 > 2% 算正样本？）
     排序不需要阈值，天然适合「选最好的 N 只」这个目标
  2. 分类会把「涨 0.1%」和「涨 8%」都标为 1（正样本）
     排序保留了「涨 8% 比涨 0.1% 更好」的信息
  3. 最终比赛评分的 Ranking Score 本身就是排序指标
     用排序目标训练 → 和评测指标天然对齐
```
